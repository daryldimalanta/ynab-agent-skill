# Receipt memos

Use the current user's explicitly requested format or private installation preferences. No personal memo style, venue, trip purpose, or automation marker is a distributed default. When no style is supplied, use a concise receipt-supported description. Never copy illustrative amounts or wording into an actual proposal.

## Amounts, tips, and units

Preserve printed precision and meaningful receipt detail. Distinguish the payable pre-tip amount from a separately documented tip; do not count included gratuity twice or infer a tip from an unmatched charge. Preserve trailing zeros and exact decimal arithmetic when checking amounts. Missing or illegible evidence remains unresolved and blocks drafting.

For fuel or other unit-priced purchases, read the unit price and quantity independently. Their precision need not match transaction currency precision. Preserve the original units and never silently convert them. Check their product at the receipt's stated precision and account for documented discounts, taxes, and other items. Do not invent a quantity, price, tax, or total to make a preferred format fit.

## Parent and category-line memos

The parent describes the whole transaction. Each split memo describes only that allocation. Attribute any base/tip/tax portions from receipt evidence or explicit instructions, reconcile the portions to the total, and show rounding choices for review. Do not repeat the full receipt tip in every allocation.

Preserve existing ownership, reimbursement, venue, and purpose details when proposing a replacement, but add them only when supported by the receipt or explicit context. A payee convention does not establish a category or authorize changing the payee.

Review the exact parent and line memos with their amounts. Respect the 500-character limit without silent truncation. Null/omitted parent memo preserves existing text; an empty string explicitly clears it. Formatting alone does not authorize rewriting splits, changing approved transactions, or applying a draft.

## User-defined markers

Use a marker only if the current user explicitly requests it or enables it in private preferences. For a requested trailing parent-only marker, retain one copy, account for its separator in the length limit, and preserve meaningful text. Allocation memos retain their own descriptions. Explicit clear/preserve instructions take precedence. A marker in a proposal is not proof that any operation was applied or approved.
